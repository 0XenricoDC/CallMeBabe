## Phase Goal

**As a** developer (or the owner using a headset), **I want to** run `python main.py --tenant=demo` and hold a natural, low-latency Italian conversation with the bot — interrupting it mid-sentence, hearing a personalized greeting, and seeing per-stage latency numbers — **so that** every architecture decision expensive to retrofit (streaming, barge-in, latency instrumentation, interface seams) is locked in before booking, telephony, and multi-tenant work begins.

<objective>
Lay the Walking Skeleton bones: a Python 3.12 environment, the full dependency set, the pytest harness with RED test stubs for every Phase 1 requirement, the typed tenant-config layer backed by a real SQLite read/write, the interface seams that Phases 2–5 extend, and the `.env.example` + README that make "clone and fill `.env`" sufficient to run the project.

This plan delivers SETUP-01 end-to-end and the config/persistence spine the live pipeline (Plan 02) builds on. It does NOT assemble the voice pipeline — that is Plan 02.

Purpose: A reproducible environment, a config seam (`TenantConfig` + `TenantRepository`), and failing tests that define "done" for the whole phase.
Output: Installable project, seeded `demo` tenant in SQLite, interface stubs, `.env.example`, README setup section, RED pytest stubs.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI `--tenant` arg → SQLite query | Untrusted process input reaches the DB layer |
| `.env` secrets → process / logs | API keys must never reach source, VCS, or logs |
| PyPI package names → install | Dependency-confusion surface (pipecat-ai vs pipecat) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-SQLI | Tampering | `TenantRepository.get_tenant` | mitigate | Parameterized `WHERE id = ?` with tuple param; acceptance criterion forbids f-string/`.format` of tenant_id (Task 3) |
| T-01-KEY | Information Disclosure | `.env` / logs / README | mitigate | `.env.example` placeholders only; README forbids committing `.env` and logging raw keys; only last-4 chars ever logged (Task 4) |
| T-01-DC | Tampering | `pyproject.toml` installs | mitigate | Pin official names+versions; install `pipecat-ai` not `pipecat`/`pipecat-flows` (Task 2). Packages are `[ASSUMED]` (slopcheck registry unreachable at research time) but all from official orgs — canonical, no human-verify gate required per RESEARCH §Package Legitimacy Audit |
| T-01-VID | Information Disclosure / config error | `TenantConfig.voice_id` | accept | Empty voice_id falls back to default English voice (wrong, not a security risk) — mitigated by Pydantic non-empty validator (Task 3) |
</threat_model>
