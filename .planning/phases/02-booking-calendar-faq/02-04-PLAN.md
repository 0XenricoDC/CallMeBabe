<objective>
Third vertical slice: per-tenant FAQ. Hours and services answer directly from the structured TenantConfig fields; address, prices, and free-text questions answer from a per-tenant SQLite FTS5 knowledge base via a `faq_lookup` tool; when nothing matches, the bot honestly says it has no answer and offers to take note (no hallucination). Includes the demo restaurant KB content and the live end-of-phase verification checkpoint.

Purpose: Closes FAQ-01/02/03 and SC4/SC5. This slice adds the FAQ node to the existing greeting→booking flow graph so a caller can ask questions or book in the same call, with strict tenant isolation on every KB query.
Output: SQLiteFTSKnowledgeBase, KB ingest, faq_lookup tool + FAQ node, demo KB text files, hybrid routing; FAQ tests go green; end-of-phase human verification of live booking + FAQ behavior.
</objective>

| Boundary | Description |
|----------|-------------|
| caller speech → faq query | free-text query becomes an FTS5 MATCH argument — untrusted |
| faq handler → kb_chunks | tenant_id (session) + query reach the FTS5 table |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-12 | Tampering | FTS5 MATCH injection | mitigate | `MATCH ?` parameterized; natural-speech operators sanitized or OperationalError caught (Pitfall 6); test with "orari e prezzi". |
| T-02-13 | Information Disclosure | cross-tenant KB leakage | mitigate | Every search is `WHERE tenant_id = ?` scoped from session tenant, never caller input (FAQ-03/SC5); test_tenant_isolation enforces. |
| T-02-14 | Spoofing | hallucinated FAQ answer | mitigate | Grounding rule + found=False fallback (D-08, FAQ-02); FAQ node answers only from config/FTS5; test_faq_not_found_routes_fallback. |
</threat_model>
