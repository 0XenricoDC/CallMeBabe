<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller speech -> notification destination | Risk of routing the summary to a caller-chosen target |
| env -> channel constructors | Tokens/SMTP creds cross into channel objects |
| summary/transcript -> outbound channel | PII leaves the system to owner channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-NINJ | Tampering | NotificationChannelFactory / channel ctors | mitigate | Channel targets (chat_id, SMTP_TO, token) read only from env via factory; `tenant` config selects the channel name; zero influence from caller args/transcript. |
| T-03-LOGPII | Information Disclosure | channel except handlers | mitigate | On send failure log `type(exc).__name__` + status code only; never subject/body. |
| T-03-TOK | Elevation of Privilege | TELEGRAM_BOT_TOKEN / SMTP_PASSWORD | mitigate | Secrets via `.env` (gitignored), placeholders in `.env.example`; never hardcoded or logged. |
| T-03-FIN | Denial of Service | finally-block notification | mitigate | Notification dispatch wrapped so a channel error is caught and logged; call shutdown never blocked. |
</threat_model>
